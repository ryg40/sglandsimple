# Deep-agent (Stage 4)

Planner + builder subagent pair exposed as MCP tools. Splits work across
two LLMs so any single conversation stays well under 80k tokens.

## Roles

| Role | Endpoint env | Default | Purpose |
| --- | --- | --- | --- |
| Planner | `PLANNER_BASE_URL`, `PLANNER_MODEL`, `PLANNER_API_KEY` | falls back to `UPSTREAM_*` | Decomposes a goal into a typed `Plan` of MCP tool calls. |
| Builder | `BUILDER_BASE_URL`, `BUILDER_MODEL`, `BUILDER_API_KEY`, `BUILDER_MAX_TOKENS` | falls back to `UPSTREAM_*` | Executes each step and summarises results. |

Set `BUILDER_*` to a second OpenAI-compatible endpoint to run the two
roles on different models. Leave `PLANNER_*` unset to keep the planner
on the existing `UPSTREAM_*` endpoint. `BUILDER_MAX_TOKENS` caps the
output token budget for builder LLM calls (summarization + final summary);
set to `60000` for the APEX model to prevent runaway responses.

## Tools exposed

| Tool | Input | Output | Use when |
| --- | --- | --- | --- |
| `plan_task` | `{goal, context?}` | Plan JSON + markdown | You want to inspect the plan before running it. |
| `run_plan` | `{plan_id}` or `{plan}` | Run summary JSON + markdown | You already have a plan to execute. |
| `deep_agent` | `{goal, context?}` | Plan + summary | One-shot: plan and execute in a single call. |

## Plan shape

```jsonc
{
  "plan_id": "<uuid>",
  "goal": "…",
  "rationale": "…",
  "steps": [
    {
      "id": "s1",
      "tool": "ask_data",            // any non-deep-agent MCP tool
      "args": { "question": "…" },
      "parallel": false,
      "depends_on": [],              // step ids this one waits for
      "rationale": "…"
    }
  ]
}
```

The planner is restricted to MCP tools other than `plan_task`,
`run_plan`, `deep_agent`, `chat`, `summarize_text`, and `echo`. Unknown
tool names are rejected at plan-validation time (see
`mcp/deep_agent/models.py` and `catalog.py`).

## Builder execution model

`run_plan` runs the plan as a LangGraph state machine:

1. Pick the next batch of steps whose `depends_on` are all complete.
2. Steps with `parallel=True` in the batch fan out via LangGraph
   `Send(...)` and execute concurrently.
3. Each step calls the existing MCP tool dispatcher (`server._dispatch_tool`)
   — same allowlist, same error semantics, same `isError` flag.
4. Oversized outputs (>4k tokens) are condensed by the builder model
   before being stored in `StepResult.output`, so later steps stay
   within `DEEP_AGENT_BUDGET_PER_CALL`.
5. First step failure triggers a single re-plan via the planner role;
   second failure ends the run with `RunSummary.error` set.
6. A short natural-language wrap-up is generated by the builder model.

Plans land in `db.deep_agent_plans`; runs land in `db.deep_agent_runs`.
Both keyed by `plan_id`.

## Sandbox

The builder has four sandboxed tools rooted at `/sandbox`
(bind-mounted from `./sandbox` on the host, owned by uid 1000):

| Tool | Notes |
| --- | --- |
| `fs_read(path)` | Reads up to 256 KB; binary returned as replacement-character UTF-8. |
| `fs_write(path, content)` | Creates parent dirs as needed. Owns files as uid 1000. |
| `fs_edit(path, old_string, new_string)` | Exact-string replace; `old_string` must be unique in the file. |
| `shell_exec(cmd, timeout_sec?)` | Runs `bash -lc <cmd>` under `runuser -u sandbox`. CWD is `/sandbox`. Default 30s timeout. |

Paths are resolved with `safe_path()` (see `mcp/sandbox.py`) before any
I/O happens — absolute paths and traversal are rejected with
`SandboxError`.

## Configuration

`.env.local`:

```
PLANNER_BASE_URL=                          # leave blank to inherit UPSTREAM_*
PLANNER_MODEL=
PLANNER_API_KEY=
BUILDER_BASE_URL=http://192.168.29.129:9292/v1
BUILDER_MODEL=Qwen3.6-35B-A3B-APEX-MTP-I-Balanced
BUILDER_API_KEY=dummy
BUILDER_MAX_TOKENS=60000                   # output token budget for builder calls
DEEP_AGENT_BUDGET_PER_CALL=70000           # per-LLM-call token ceiling
DEEP_AGENT_MAX_STEPS=25                    # hard cap on plan length
DEEP_AGENT_MAX_SECONDS=600                 # hard cap on total run time
```

## Smoke test

```bash
./scripts/smoke_deep_agent.sh
```

Drives `deep_agent` end-to-end against the live stack, asserts that
files land in `./sandbox/`, and confirms Mongo persistence. Exits
non-zero on any failure.

## Verifying the endpoint split

Inside the running container:

```bash
docker compose exec mcp python3 -c "
from llm import llm_client, llm_model
for role in ('planner', 'builder', 'default'):
    cli = llm_client(role)
    print(f'{role}: base={cli.base_url} model={llm_model(role)}')
"
```

Should print two distinct `base_url` + `model` combinations when
`BUILDER_BASE_URL`/`BUILDER_MODEL` are set.

## Observability

Every LLM call emits a single structured log line:

```
[deep_agent.budget] role=<planner|builder> kind=<request|step_start|summarize_step|final_summary|...> tokens=N budget=70000 <k=v>...
```

Grep these to confirm role split, audit token use, and trace step
execution order.

## Known limits

- The planner sometimes emits `PLACEHOLDER_CONTENT` for `fs_write` when
  the step depends on a prior `ask_data` result. The builder dispatches
  the literal placeholder — there's no per-step LLM refinement yet.
  Workaround: phrase goals so the file content is computable from the
  goal itself, or split into two `deep_agent` calls.
- Builder LLM is currently used only for output condensation and the
  final summary, not for per-step tool-arg refinement. That's a future
  enhancement; the architecture leaves room for a per-step tool loop.
- Re-plan is one-shot. Goals that need multiple corrective passes will
  exit with `RunSummary.error`.
